# java-lotto-precourse

# 로또

## 주요 기능 목록

- [x] 로또 구입 금액 입력 받기
    - [x] "구입금액을 입력해 주세요." 메시지를 출력한다.
    - [x] 구입 금액은 1000원 단위이다. (1000으로 나누어 떨어져야 한다)
    - [x] 입력 금액을 통해 구매 가능한 로또 개수를 계산한다.
- [x] 로또 번호 출력하기
    - [x] 구매한 로또 개수를 출력한다.(ex. 8개를 구매했습니다.)
    - [x] 1 ~ 45 사이의 숫자로 중복되지 않는 6개의 숫자를 무작위로 뽑는다.
    - [x] 각 로또 번호는 오름차순으로 정렬하여 출력한다.
    - [x] 출력형식은 [1, 2, 3, 4, 5, 6] 형태이며 숫자 구분자는 ,이다.
- [x] 당첨 번호 입력 받기
    - [x] "당첨 번호를 입력해 주세요." 메시지를 출력한다.
    - [x] 1 ~ 45 사이의 중복되지 않는 6개의 숫자를 입력받는다.
- [x] 보너스 번호 입력 받기
    - [x] "보너스 번호를 입력해 주세요." 메시지를 출력한다.
    - [x] 1 ~ 45 사이의 당첨 번호와 같지 않은 숫자를 입력 받는다.
- [x] 당첨 통계 출력
    - [x] "당첨 통계" 메시지를 출력한다.
    - [x] 아래와 같은 형식으로 당첨 결과를 출력한다.
   ``` 
   ---
     3개 일치 (5,000원) - 1개
     4개 일치 (50,000원) - 0개
     5개 일치 (1,500,000원) - 0개
     5개 일치, 보너스 볼 일치 (30,000,000원) - 0개
     6개 일치 (2,000,000,000원) - 0개
   ```
-  [x] 수익률 출력
    -  [x] 당첨 통계를 바탕으로 총 수익률을 계산해서 다음과 같이 출력한다.
    -  [x] 수익률은 소수점 둘째 자리에서 반올림한다.(ex. 100.0%, 51.5%, 1,000,000.0%)
   ```
     총 수익률은 62.5%입니다.
   ```

### 예외 사항 처리

- 사용자가 잘못된 값 입력시 ```IllegalArgumentException```를 발생시키고 ```"[ERROR]"```로 시작하는 에러 메시지를 출력 후 그 부분부터 입력을 다시 받는다.
- [x] **구입 금액**
    - 숫자가 아닌 경우
    - 음수나 소수 같이 나눌 수 없는 숫자의 경우
    - 1000원으로 나누어 떨어지지 않는 경우
- [x] **당첨 번호**
    - 숫자가 아닌 경우
    - 구분자가 쉼표(,)가 아닌 경우
    - 1~45 사이의 숫자가 아닌 경우
- [x] **보너스 번호**
    - 숫자가 아닌 경우
    - 1~45 사이의 숫자가 아닌 경우
    - 이미 나온 당첨 번호와 중복되는 경우

## 구현시 고려한 부분

### 메인 로직 및 구조 설계

- Controller에 과도한 책임을 부여하지 말자
    - 생성자 부분은 `AppConfig`나 `AppFactory` 형태로 넣자.
    - 컨트롤러에 함수 하나가 아니여도 되고 역할 단위로 분리하자
- 한 클래스에 여러 기능을 담지 말자
    - 단일 책임 원칙을 지키자
    - 테스트 용이성을 높이자
- 배열대신 컬랙션을 활용하자.
    - 데이터 조작이 용이한 `List`, `Set`, `Map`을 활용하자
    - 변수 이름에는 자료형을 포함하지 말자.
- 하드 코딩하지말자
    - 메시지, 상수 등은 별도로 관리하자
    - 오류 메시지는 `enum` 형태로 분리하자
    - 원시값은 가능한 래핑하자
- 구현 순서 신경쓰자
    - 상수 -> 인스턴스 변수 -> 생성자 -> 매서드 순서 지키자
- 공백 관련
    - 의미 없는 공백은 만들지 말자
    - 가독성 위한 구분 공백을 만들자
- 생성자 관련
    - 함수형 인터페이스일 경우 ```@FunctionalInterface```을 활용하자
    - 모든 메서드가 `static`인 유틸리티 클래스는 `private` 생성자를 선언해 인스턴스화를 막자

### 테스트 코드 작성 시 고려 사항

- 중복되는 테스트는 최소화하자
    - ```@ValueSource(strings = {"", " ", " "})``` 이런 방식으로 테스트가 된다.
- 작은 테스트부터 단위 테스트 하자.
    - 단위 테스트 -> 통합 테스트 순으로 확장하자
    - 검증 단위별로 세분화된 테스트를 작성하자
